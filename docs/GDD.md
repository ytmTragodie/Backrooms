## 1. 体验目标

玩家身处难以理解的后室环境，靠有限手牌与资源探索、处理实体威胁、辨识环境规律，并在风险累积前找到切出路线。

**核心选择**：本回合用 3 AP 保命、调查、争取收益，还是尽快切出？未知信息、有限资源、牌组构筑和楼层风险必须形成有意义的取舍。游戏优先追求**即时反馈、风险收益、重复游玩变化**，而不是单纯堆更多进度条与文本。

首个垂直切片仍以 Level 0 / Level 6、Hound / Smiler、有限卡池与装备为核心，不擅自扩展大量层级、制作和元进度。数字以现有原型为基线，未经授权不批量调平衡。

## 2. 单一行动经济：玩家牌是主要主动入口

- 每回合基础 3 AP，基础手牌目标 5 张；每个全局回合至多额外获得 1 张装备生成牌的机会。统一手牌与目标选择，不分“探索模式/战斗模式”。
- **一张牌只有一个主动作语义**。可以因目标或环境改变效率，但不能展开攻击/观察/搜索/熄灯等不同动词的操作菜单。
- NORMAL：永久牌组，抽牌/弃牌/洗牌与构筑；EQUIPMENT：持久物品生成临时行动牌；FLOOR_TEMPORARY：本次楼层产生的切出等机会。装备本体与世界卡不进入永久牌堆。
- End Turn、暂停、只读卡牌说明、合法目标选择是系统控制；主动攻击、搜索、观察、设备操作和切出尝试通过真实手牌发起。**已赢得的奖励选择、安全点决策、切出成功后的地图选路属于流程选择，不可扩展成常驻免费玩法按钮。**

### 常用牌语义（目标设计）

| 语义               | 玩家做的事情                                                 | 不应自动做的事情                                             |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 观察 `OBSERVE`     | 揭示一个有效目标/局势中**尚未知晓的信息**；辨识实体规则或环境线索 | 不直接加 Supply、切出稳定度、万能推进 Objective、无条件加 Cognition |
| 搜索/探索 `SEARCH` | 主动搜索并推动楼层探索；可以发现有限资源、触发下一项遭遇或匹配可探索 Objective 的推进条件 | 没有消费者时空刷 Explore 数值；同时提供无条件全套效果        |
| 攻击 `ATTACK`      | 对合法实体造成伤害/附带已声明的攻击修正                      | 对无目标环境虚构“调查伤害”                                   |
| 防御 `GUARD`       | 获得本回合防护，抵挡声明为可格挡的伤害                       | 代替观察或搜索                                               |
| 装备/切出专用牌    | 执行名字清楚的一种专属动作                                   | 从同一张牌打开互不相关的动词列表                             |

**实现过渡说明**：旧版本 `Observe/Search → explore_amount → Objective 进度` 仍可能存在。迁移后应将“信息揭示”与“推动世界出现内容/数值推进”拆清，不允许为了减少死牌把 Observe 改成万能工具。卡牌在某些遭遇无适用目标是允许的，但必须通过卡组与遭遇节奏控制整手死牌率。

## 3. 世界内容：职责不同、外观可以统一

| 类型       | 定义                                      | 出现/交互方式                                                |
| ---------- | ----------------------------------------- | ------------------------------------------------------------ |
| Scene Rule | 本层持续环境规则，如黑暗、滞留压力        | 背景状态/信息提示，不是选中目标                              |
| Event      | 临时局势修正：DEBUFF / OMEN / OPPORTUNITY | 世界牌展示，最多 2 张；影响合法出牌及回合结算，通常不直接被玩家牌作为目标 |
| Entity     | 怪物、规则型威胁                          | 当前最多 1 个；通过同一手牌处理 HP、State、Intent、环境触发  |
| Objective  | 低频高价值的可选目标                      | 最多活动 1 个；有明确收益、风险或路线信息，可跳过            |

**Event 不是 Objective 的另一个名字**：Event 没有调查血条，不接受通用 Explore 直接打进度；它通过持续修正、预兆倒计时和成功出牌的条件监听影响局面。前端 Event 应为简洁卡片，简短状态一目了然，详细解释放悬停/只读详情/日志，避免满屏提示文字。

### 3.1 Objective：从常驻进度条变成稀有风险收益点

定位：低频、可选、高价值；可以给 Supply、卡牌奖励、CutOut/地图线索，也可以提高 Threat、制造 Omen、引来实体。**通常不作为楼层切出的硬前置条件。**

三种解决方式：

| 类型        | 规则                     | 示例与反馈                                               |
| ----------- | ------------------------ | -------------------------------------------------------- |
| `PROGRESS`  | 短进度、分段阈值         | 受潮补给箱：推进短条，阶段打开箱盖/显露物品，完成给补给  |
| `CONDITION` | 若干独立条件，无先后顺序 | M.E.G.终端：找到电源线索和解码信号；满足项逐个亮起       |
| `SEQUENCE`  | 必须按指定步骤执行       | 空间裂隙：按线索先观察、再搜索、再尝试稳定；明确当前步骤 |

禁止把所有 Objective 统一成“0/18 Explore HP”；一次合法交互应产生可见反馈（状态文字、图像阶段、音效/轻动画、风险提示），错误步骤的后果需要事先声明。完成奖励只能触发一次；不要求每类 Objective 都有固定线索阈值、忽视压力。

**内容节奏**：Objective 不应在每个已完成目标后必然重新补上。探索/遭遇调度先决定**是否生成 Objective**，再选择哪个 Objective。普通 Event、实体遭遇、有限资源发现与短暂危机应提供更丰富的回合组成；具体频率须经种子和真人测试调整，不在此硬写百分比。短危机/剧情选择是后续候选机制，未经单独定稿不新增第二套行动栏。

### 3.2 观察与探索的闭环

- 观察的价值在于**降低不确定性**：揭示实体行为规律、隐藏风险、Objective 的条件提示、未知环境信息。已经公开的说明可免费阅读，但新信息揭示必须通过合法卡牌/规则。
- 搜索/探索的价值在于**让世界向前推进**：从声明的可用遭遇池发现资源/目标/风险或推进匹配的目标。由楼层规则决定遇到什么，不由一张搜索牌写死“召唤猎犬”。
- 同一重要 Insight 可通过不同路径发现，确认一次后只提高一次 Cognition；不要把“使用观察牌次数”直接等同认知数值。
- 若没有任何合法信息/探索消费者，应清楚地判定不合法或给予**明确设计的**替代机制；不能成功 no-op，也不能发没有来由的资源。

## 4. Entity：规则型怪物与环境互动

所有实体共享 HP、State、Intent 和条件触发；解决方式可以是击败、脱离、退去，**不要求所有怪物靠扣血解决**。例如 Hound 响应真实 NOISE 进入追逐，Smiler 因真实 LIGHT 躁动、保持黑暗可能令其退去。

环境规则应以“已实际生效的状态/效果标签”（LIGHT、DARK、NOISE 等）驱动实体的**数据化反应**，优先改变警戒状态、行为意图、可知信息，再用数值增减补充。不能只凭未成功打出的卡面标签，也不能在新怪物出现时不断加 `light_exposed/noise_exposed/...` 布尔字段。

怪物的重要行为必须可通过 UI/观察理解；规则型敌人的应对不应依赖唯一且可能错过的单张卡或事件，避免无解。

## 5. 装备、资源和局内构筑

- 三个持久携带槽（当前 Demo）；每个 `EquipmentInstance` 保存电量/耐久/次数，跨楼层保留。装备主动使用通过独立生成的“照明”“熄灯”“撬棍猛击”“饮用杏仁水”等牌，不能作为独立按钮。
- 有限资源经合法搜索结算，不能重复搜刮；玩家 Supply 是持有库存，不是 Objective 自己的属性。现在 Supply 用途有限，**新增经济消耗体系需单独设计**。
- 主要奖励可生成三选一卡牌机会；等待领取的机会阻止继续普通出牌，具体加牌/升级/移除只影响合法 NORMAL CardInstance，不能误改装备或楼层牌。
- 构筑与装备补充要服务于“留下探索还是冒险切出”的风险收益，不引入没有玩法意义的素材/货币膨胀。

## 6. 切出、地图和安全点（下一阶段重要方向）

### 6.1 CutOut → 地图选路

离层牌仍通过楼层机会进入统一手牌；仓促与安全切出是明确的 CardData。满足合理兜底条件应有切出机会，不能因资源耗尽或错过唯一 Insight 永久困住玩家，但仓促离层可以有明确风险。

**目标交互流**：

```text
打出切出牌 → 成功判定 → 生成约 2 个可选目的地节点
→ 打开本局地图/路线信息 → 玩家选择 → 切换至目标 FloorState
```

RunMapState 应记录已访问楼层与已发现路线；安全切出比仓促切出提供更清晰的目的地信息。首版是简洁的双路线选点，不要求复杂的《杀戮尖塔》式全图；每个节点给足够简短、可用于决策的环境线索。

**仓促切出失败（最新目标规则）**：未打出的临时牌可 Retain；**已打出失败则从手牌弃置，之后需重新抽到**，不允许立即原位再次点击。楼层临时弃牌/回收机制必须明确且不污染 NORMAL 永久牌组、不能导致无牌可出；这项变更与旧“失败保牌”的代码/历史测试可能不一致，需要单独迁移验证。

### 6.2 一次性 Safe Point

Safe Point 是特殊“机会”而不是常驻整备按钮。条件满足、允许呈现时**立即弹出“进入 / 放弃”**；放弃即永久错过本次机会，进入后可在有限选项中休整、升级或删牌。安全点选择不消耗普通卡牌行动，不得被复用成任意时间可呼出的免费资源管理器。被实体威胁/待选奖励阻挡时，触发和展示时机需保证逻辑一致。

## 7. 玩家反馈、视觉与测试

- 卡片显示应将**背景、卡框、插画、动态文字、图标、数值**分离；素材通过稳定 asset ID 读取、缺失有回退。世界牌外观统一不意味着它们共享一个业务 CardData。
- 表现优先级：打牌反馈、伤害/格挡与敌人意图、Objective 每次推进的阶段反馈、Event 状态变化、奖励选择、CutOut 地图过场。少写长解释，靠视觉变化让玩家理解后果。
- 玩家界面简体中文；日志可保留英文稳定 ID 与结构化上下文。
- 评测不仅检查“能通关”，还要观察：无效手牌比例、每回合是否有决策、重复 Objective 的疲劳感、危险是否能提前预判、奖励是否值得冒险、两个路线是否有取舍。
- 维持基本不变量：单回合与单 AP 池、失败无半次扣费、有限资源、唯一 Insight、不重复奖励、实体行为不脱离统一流程、Seed 可复现、切出防永久软锁。

## 8. 实现边界及待验证设计

**已存在的历史原型**：Level 0/6、Card-First 单手牌、Event/Objective/Entity 分离、装备生成牌、Hound/Smiler、CardReward、Safe Point、基础 CutOut 等；**具体可运行行为必须由仓库验证**。

**尚需分步落实/验收的目标**：Objective 三模式与低频生成、观察/搜索语义调整、环境实体通用反应、一次性 Safe Point、RunMapState/双节点选路、切出失败弃置重抽、简洁 Event UI。它们不是“编辑这份 GDD 就已经完成”的功能；AI 不得绕开确认直接大规模修改代码。

实施顺序建议：先理清状态归属与分域 ActionResult → Objective 三模式/奖励与生成节奏 → Observe/Search 的信息与世界推进机制 → Event/实体环境反应和即时反馈 → Safe Point → CutOut 地图与失败回收。各阶段优先维持可运行、可测试的小闭环。

# 26.10.21 13：42 最新版本更新
Phase 14：从探索驱动重构为地图驱动的战斗 Roguelike
更新的版本应该有四个原则
- 地图负责推进游戏：玩家在楼层内选择节点，决定路线和风险，不再依靠观察、搜索牌推进探索进度。
- 战斗是卡牌的主要使用场景：攻击、防御、情报、装备等体系在同一个遭遇战斗中发挥作用。
- 非战斗事件通过选项解决：事件可以消耗资源、触发战斗、改变路线，但通常不进入出牌界面。
- 公开意图保证策略性，职业机制提供差异性：所有角色都能看到当前敌人的行动意图，M.E.G. 探索者则通过情报体系提前规划、识破弱点、干预敌人行动。(目前还没有扩展职业机制，后续会加入)

重新划分游戏阶段：
1. 地图阶段：玩家选择节点，决定路线和风险。
2. 遭遇阶段：玩家在节点中进行战斗、事件或奖励（奖励选择，补给等）、休息点（生命回复、卡组调整、装备更换等）、楼层切出出口
3. 结算阶段，返回地图
