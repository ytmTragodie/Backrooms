## 修改
支持三种 Objective,Progress、Condition、Sequence，分别对应不同的类型。
PROGRESS
短进度目标，例如 0/6，并带阶段反馈
比如 受潮补给箱 类型：PROGRESS  进度 0/6 
2：确认箱内有物资
4：撬开外层
6：完成，获得补给

CONDITION
满足若干条件，例如“使用过观察 + 搜索”
M.E.G. 终端
类型：CONDITION

□ 使用观察
□ 使用搜索
□ 本回合没有受到伤害

全部满足 → 完成

SEQUENCE
按顺序完成，例如“观察 → 搜索 → 使用工具”
空间裂隙
类型：SEQUENCE

观察
→ 搜索
→ 再使用一张观察类牌
→ 完成


## Objective 设计目的
具体逻辑上，Objective 最好只保留几种结果类型：
- 奖励型：补给箱、终端、资源缓存
- 路线型：地图信息、出口信息、降低仓促切出风险
- 诱敌型：高收益，但提高 Threat / 生成 Omen / 引来 Hound
- 交换型：消耗 HP、压力、装备耐久换奖励

# 2026.10.20  优化思路
Phase 14：从探索驱动重构为地图驱动的战斗 Roguelike
更新的版本应该有四个原则
- 地图负责推进游戏：玩家在楼层内选择节点，决定路线和风险，不再依靠观察、搜索牌推进探索进度。
- 战斗是卡牌的主要使用场景：攻击、防御、情报、装备等体系在同一个遭遇战斗中发挥作用。
- 非战斗事件通过选项解决：事件可以消耗资源、触发战斗、改变路线，但通常不进入出牌界面。
- 公开意图保证策略性，职业机制提供差异性：所有角色都能看到当前敌人的行动意图，M.E.G. 探索者则通过情报体系提前规划、识破弱点、干预敌人行动。(目前还没有扩展职业机制，后续会加入)
