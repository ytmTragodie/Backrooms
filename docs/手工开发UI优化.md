## 任务一：地图生成规则扩展

目前地图主要依赖随机生成，希望在保留随机性和路线多样性的基础上，引入可配置的生成规则，使节点之间具有合理的关联，提升地图的策略性和趣味性。

例如：

- **前置情报：** 在某些特殊实体或精英节点前方 2～3 层，安排可能揭示其弱点的事件节点，让玩家有机会提前准备。
- **战后补给：** 在高危险战斗节点之后，适当安排休息、补给或奖励节点，避免难度分布过于极端。
- **风险与收益：** 高风险路线可以对应更高价值的奖励，鼓励玩家主动权衡。
- **节奏控制：** 避免连续出现过多高危险节点，同时保留少量特殊的高风险路线。
- **楼层差异：** 不同 Level 可以配置不同的节点分布和生成规则。

### 设计要求

1. 基于现有地图生成器扩展，不推翻当前 DAG 地图结构。
2. 采用**基础随机生成 + 可配置规则约束/修正 + 最终合法性验证**的思路。
3. 生成规则应当能够通过 Resource 或现有配置体系扩展，避免在生成器中大量硬编码。
4. 区分强制规则与倾向性规则，避免规则过多导致地图千篇一律。
5. 对于前置情报类节点，需要考虑不同路线是否真正能够到达该节点，不能仅根据节点编号或视觉距离判断。
6. 确保生成后的地图仍然存在合法、可通行的路线。
7. 支持固定随机种子测试，方便验证规则是否有效。
8. 预留后续支持地图中移动实体、动态遭遇的扩展空间，但本任务暂不要求实现实体巡逻和追猎。

请结合现有代码，提出合理的规则配置结构，并选择少量具有代表性的规则进行验证，不需要一次实现完整的复杂规则引擎。

## 任务二：楼层扩展与跨 Level 大地图

当前可探索的 Level 数量较少，希望逐步扩充不同主题、环境、实体和事件的楼层。

同时，希望新增一个**跨 Level 的大地图（Level Network）**，与现有的 Level 内部节点地图形成联动。

### 目标设计

**Level 内部小地图：**

- 负责当前 Level 的节点移动、事件、战斗、资源与出口选择。
- 保留当前非线性 DAG 结构。
- 节点位置与连接关系可见，部分节点内容保持未知。
- 玩家仍然通过实际探索抵达出口。

**跨 Level 大地图：**

- 展示玩家已发现、已访问的 Level。
- 记录不同 Level 之间已知的切出联系。
- 展示不同出口可能对应的目标 Level、入口及概率信息。
- 未被发现的 Level 或切出关系可以保持未知。
- 玩家可以查看楼层之间的联系，为后续探索制定路线。

### 切出规则

1. 保留**普通 CutOut 必定成功、目标 Level 按概率抽取**的基本机制。
2. 不同出口可以配置不同的目标 Level 和概率分布。
3. 出口和入口可以有不同的进入条件，例如需要特定情报、道具或完成某个事件。
4. 玩家可以根据已知信息选择可到达的出口或切出路线，但不能通过大地图直接传送到任意 Level。
5. 同一局游戏中重新进入已访问 Level 时，应当保留此前生成的地图、节点状态与探索记录，不重新生成。
6. 需要考虑重复进入的落点、已结算节点和出口的处理，避免软锁及重复领取奖励。
7. Knowledge 仍然是长期已知信息集合，不新增通用情报点数。

### 扩展性要求

- 楼层内容、入口、出口和概率连接尽量数据驱动。
- Level 大地图应当基于实际楼层与切出数据生成，而不是维护一套独立且容易不一致的硬编码关系。
- 不同 Level 应能配置主题、节点权重、事件池、实体池及特殊规则。
- 优先设计可扩展的楼层网络框架，再逐步填充实际 Level 内容。
- 不要未经确认就大量生成新楼层和占位内容。
